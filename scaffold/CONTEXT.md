# Glossary

Canonical domain vocabulary for this project. Grill / domain-modeling write here.
Keep entries short. Deeper invariants go in `docs/domain/<topic>.md` and link from here.

Use these terms in specs, tickets, commits, and code names. Synonyms listed under `_Avoid_` must not be used as the domain name.

A heading here is addressed `TERM:<anchor>` — `## Event envelope` is
`TERM:event-envelope` — and node files cite that address on their `Refs:` line
rather than repeating the definition ([`docs/method/addressing.md`](docs/method/addressing.md)).

**Method vocabulary never enters this file.** Node, address, axis, gate, packet,
stage, work type and projection describe how work is run, not what this product is
about; they are defined once in [`docs/method/glossary.md`](docs/method/glossary.md).
A reader opening this file wants to know what a domain word means, and a process
rubric sitting between two domain terms is what makes them stop opening it.
